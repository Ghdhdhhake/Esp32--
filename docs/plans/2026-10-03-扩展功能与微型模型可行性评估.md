# 扩展功能清单 + 微型模型（TinyML）可行性评估

**日期：** 2026-10-03
**评估对象：** `F:\ESP32\Esp32_Projects\sample_project`（单板设备仪表盘）
**结论一句话：** 微型模型**能加**，但只限于「几十 KB 级」的离线分类模型（关键词唤醒 / 传感器分类 / 异常检测）；**本地大模型对话在 ESP32 经典款上不可能**，差 3 个数量级。网页对话要走「云端 LLM + 板子做工具调用」的路线。

## 一、先算清楚家底（全部从本工程实测）

### 1.1 硬件与构建配置

| 项 | 实测值 | 来源 |
|---|---|---|
| 芯片 | **ESP32 经典款**（Xtensa LX6 双核） | `CONFIG_IDF_TARGET="esp32"` |
| CPU 主频 | **160 MHz** | `CONFIG_ESP32_DEFAULT_CPU_FREQ_MHZ=160` |
| IDF 版本 | **v5.5.5** | map 中 `F:/ESP32/Espressif/v5.5.5/esp-idf` |
| Flash | **2 MB**，DIO 模式 | `CONFIG_ESPTOOLPY_FLASHSIZE_2MB=y` |
| **PSRAM** | **没有**（未启用） | `# CONFIG_SPIRAM is not set` |
| 已启用无线 | WiFi (STA+AP) + NimBLE（observer/broadcaster/peripheral/GATT） | `sdkconfig.defaults` |

### 1.2 Flash 账本

```
0x000000 ─ bootloader
0x008000 ─ 分区表
0x009000 ─ nvs        0x6000
0x00F000 ─ phy_init   0x1000
0x010000 ─ factory    0x180000  (1.5 MiB)
0x190000 ─ ────────── 空闲 ≈ 448 KB ──────────┐
0x200000 ─ Flash 结束                          │
```

| 项 | 数值 |
|---|---|
| 应用槽容量 | 1,572,864 B（1.5 MiB） |
| **当前固件** | **1,103,968 B（1.053 MiB）** |
| **应用槽剩余** | **≈ 448 KB** |
| **分区表之外的尾部空闲** | **458,752 B ≈ 448 KB** |
| **Flash 总可用余量** | **≈ 896 KB** |

### 1.3 RAM 账本

ESP32 经典款的 DRAM 堆由 `components/heap/port/esp32/memory_layout.c` 定义。本工程：

| 项 | 数值 |
|---|---|
| 蓝牙控制器硬预留 | `0x3FFB0000` 起 **0xDB5C = 56,156 B** |
| `.data` | 24,188 B |
| `.bss` | 39,004 B |
| 静态占用合计 | **63,192 B** |
| 数据段起始 | `0x3FFBDB60` |
| `_bss_end` / `_heap_start` | `0x3FFCD238` |
| **开机可用堆（DRAM，8-bit 可访问）** | **≈ 208 KB** |

> 开机 208 KB 之后，WiFi 驱动（约 50–60 KB）、NimBLE 四角色（约 40–50 KB）、
> HTTP 服务任务（栈 10,240 B）+ lwIP 缓冲 + cJSON 会陆续吃掉。
> **运行时实际可用堆预计 90–130 KB** —— 这个数字请直接看网页「设备信息」面板里的
> `free_heap` / `min_free_heap` 确认真值，不要再凭估算做决策。

### 1.4 三条硬约束

1. **没有 PSRAM** —— 这是最要命的一条。所有模型权重和推理中间张量都只能待在内部 SRAM。
2. **堆只剩 ~100 KB 量级** —— 一次 TLS 握手就要 ~40 KB。
3. **Flash 只剩 ~448 KB** —— 模型权重放 Flash 不占 RAM（走 DROM 内存映射），所以 Flash 反而比 RAM 宽松。

## 二、微型模型：能加，但要选对量级

### 2.1 可行性矩阵

| 模型 | 权重(Flash) | 推理 Arena(RAM) | 在本工程可行？ |
|---|---|---|---|
| sine / hello_world 演示 | 2.4 KB | 2 KB | ✅ 随便加 |
| **micro_speech 关键词唤醒**（4 词） | ~18 KB | 16–30 KB | ✅ **推荐** |
| **传感器分类 MLP**（温湿度/振动/电流） | 5–50 KB | 5–20 KB | ✅ **推荐** |
| 手势识别（3 轴加速度 CNN） | ~20 KB | ~15 KB | ✅ 可行 |
| 异常检测（自编码器 / 孤立森林） | 10–40 KB | 10–30 KB | ✅ 可行 |
| person_detection（96×96 灰度 CNN） | ~250 KB | **~136 KB** | ⚠️ 必须关掉 BLE 才能跑；单帧 380 ms（有 ESP-NN）～ 4084 ms（无） |
| ESP-SR 语音唤醒 / 命令词 | 数 MB | 数百 KB | ❌ 需 ESP32-S3 + PSRAM |
| microWakeWord | — | — | ❌ 官方目标是 S3 |
| **本地 LLM 对话**（TinyLlama / Qwen-0.5B 4bit） | **300 MB+** | **数百 MB** | ❌ **差 3 个数量级，无解** |

### 2.2 技术选型

**首选：`esp-tflite-micro`（乐鑫官方维护的 TensorFlow Lite Micro）**

- 安装：`idf.py add-dependency "esp-tflite-micro"`
- 要求：IDF ≥ v5.1（本工程 v5.5.5 ✅）；CI 构建矩阵包含 `esp32` 经典款 ✅
- 集成 `esp-nn` 加速（在经典款上是纯 C 回退，加速比远不如 S3/P4，但能用）
- **关键手法：模型权重用 `const` 数组放在 `.rodata` → 落到 Flash 的 DROM，通过内存映射零拷贝读取，不占 RAM。** 只有 arena 必须放 RAM。
- 本工程 `partitions.csv` 里还有 448 KB 尾部空间，也可以给模型单独开一个 raw 数据分区，用 `esp_partition_mmap()` 映射，比塞进 app 更灵活（换模型不用重刷固件）。

**次选：`esp-dl`** —— 官方文档名义上写了支持 ESP32，但它的高效算子基于 **AI 指令（向量扩展）**，经典款 ESP32 上只能走标量 C 实现，性能很差，且静态内存规划器主要为 S3/P4 的 Internal RAM + PSRAM 结构设计。**本工程不建议。**

**排除：ESP-SR / microWakeWord** —— 明确要求 ESP32-S3 及以上 + PSRAM。

### 2.3 如果一定要「板子上有模型」，最有价值的落点

不是对话，而是**离线意图分类器**：

```
I2S 麦克风 ──► 特征提取(MFCC) ──► micro_speech 模型 ──► 意图标签
                                                        │
                        "开灯" / "关灯" / "亮一点" ◄─────┘
                                  │
                                  ▼  直接调本地已有的 /api/led、/api/gpio
                            （完全离线，不联网、不上云）
```

这样本工程现有的 `/api/led`、`/api/gpio`、`/api/adc` 就变成了「本地语音控制」的执行端，
而且断网也能用。硬件只需加一个 I2S 数字麦克风（如 INMP441 / ICS-43434，约 10 元）。

## 三、关于「网页对话」（不用屏幕）

### 3.1 先澄清一件事

你给的 `https://github.com/egger435/egg-nano` **是 404，仓库不存在**。
`egger435` 账号下的公开仓库有 TFbot、EGGER-Vision、Mini_Oscilloscope、EGGER_1/2 等，
**没有任何叫 `egg-nano` 的项目**。GitHub 全站搜索 `egg-nano` 也没有匹配的 ESP32/AI 项目。

所以「能不能整合进来」这个问题目前**无法评估** —— 请确认仓库名是否记错了，或者项目是否已改名/转私有。

顺便说明：网上常见的 ESP32 AI 对话项目（`xiaozhi-esp32`、`14790897/ESP32-AI-Chat`、
`zhangheng18/esp32-ai-chat`）**绝大多数目标板是 ESP32-S3（带 PSRAM）**，
移植到本工程的 ESP32 经典款上，凡是涉及「本地语音识别 / 本地模型」的部分都跑不起来。

### 3.2 本工程做网页对话的推荐架构

**方案 A —— 网页做 UI，板子做工具（推荐，改动最小）**

```
浏览器 (对话 UI + 历史记录) ──► 云端 LLM API（直接 fetch 或经板子代理）
        │
        └─► function calling ──► 板子现有 REST API
                                   /api/led  /api/gpio  /api/adc
                                   /api/scan /api/ble/status
```
- 板子完全不碰模型，只把已有的 12 条 REST 路由包装成 LLM 的 tool schema
- 对话历史、Markdown 渲染、流式输出全在浏览器端做（前端已有 44 KB 的 index.html 底子）
- 风险最低：不占堆、不占 Flash

**方案 B —— 板子做网关**

```
浏览器 ──WebSocket──► ESP32 ──HTTPS──► 云端 LLM API
```
- 板子需要跑 mbedTLS 客户端：TLS 握手峰值 **~40 KB 堆**，要小心
- 必须做流式（SSE / chunked）转发，不能整段收完再发，否则堆必爆
- 网页要从 2 秒轮询改成 WebSocket（顺带解决现有轮询的开销）

**方案 C —— 混合（体验最好）**

本地 micro_speech 做唤醒词 + 短指令（离线、零延迟），长对话交云端。
这是「小智」那类产品的实际做法。

### 3.3 如果还是想整合某个开源项目

判断它能不能落到本工程的**三个检查点**：

1. `idf.py set-target` 用的是什么？是 `esp32s3` 还是 `esp32`？—— S3 的项目移植到经典款，凡是依赖 PSRAM / AI 指令 / ESP-SR 的部分都要重写。
2. 它的分区表要求多大 app 槽？本工程只剩 448 KB。
3. 它常驻多少堆？本工程运行时只剩 90–130 KB。

### 4.1 OTA 的坑（重要）

OTA 需要**两个等大的 app 槽**。当前 app 已经 1.05 MB，`1.05 × 2 = 2.1 MB > 2 MB Flash`，**装不下**。

三条出路：
- **换 4 MB Flash 的板子**（最省事，ESP32-WROOM-32E 4MB 版十几块）
- 把 app 槽压到 ~0.9 MB（要把 44 KB 的 `index.html` 挪到 LittleFS、砍掉部分功能），再加一个 0.9 MB 的 ota_0 槽
- 只做「网页上传固件到数据分区 → 重启从该分区引导」的半套 OTA，改动大、收益低，不推荐

**在没换板子之前，不建议动 OTA。**

## 五、风险清单

| 风险 | 说明 | 应对 |
|---|---|---|
| **堆紧张** | 运行时只剩 90–130 KB；TLS 握手 ~40 KB；cJSON 序列化 30 条 AP 记录会瞬时吃掉几 KB | 流式收发、复用缓冲、必要时推理前 `esp_wifi_stop()` 或关 BLE |
| **单射频共存** | WiFi 与 BLE 分时复用，跑 AI 推理时会互相抢 | 推理放低优先级任务；已设 `WIFI_PS_NONE`，保持 |
| **主频只有 160 MHz** | 提到 240 MHz 可换 ~50% 推理性能 | `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y` |
| **app_main 栈只有 3584 B** | 之前已经踩过栈溢出（见 main.c 注释） | 模型初始化放独立任务，栈 ≥ 8 KB |
| **Flash 只剩 448 KB** | 大模型权重塞不进 app 槽 | 用独立 raw 分区 + `esp_partition_mmap()` |
| **无真机验证** | 以上内存数字来自 map 静态分析，运行时会变 | 上板后读「设备信息」面板的 `free_heap` / `min_free_heap` 复核 |

## 六、建议的下一步

1. **确认 `egg-nano` 的真实地址**（现在这个 404），否则无法评估整合方案。
2. 上板后记下「设备信息」面板里的 `free_heap` 和 `min_free_heap` 真值 —— 这是后面所有决策的分母。
3. 若目标是「网页 AI 对话」→ 走**方案 A**（网页 + 云端 LLM + 板子 function calling），改动最小、风险最低。

   把已有的 LED/GPIO 控制变成离线语音指令。
5. **暂时不要碰 OTA**，除非换 4 MB Flash 的板子。
